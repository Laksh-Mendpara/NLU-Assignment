🔬 Problem 4: Methodology

Feature Representation Techniques

1. Bag of Words (BoW)

Represents each document as a frequency count of words, ignoring grammar and word order but maintaining word frequency information. Simple yet effective for many classification tasks.

2. TF-IDF (Term Frequency-Inverse Document Frequency)

Weighs terms based on their importance in a document relative to the entire corpus. Terms that appear frequently in one class but rarely in others receive higher weights, making them more discriminative features.

TF-IDF(term, doc) = TF(term, doc) × IDF(term) IDF(term) = log(total_docs / (1 + docs_containing_term))

3. N-grams

Captures sequences of n consecutive words, preserving some local word order information. Implemented support for unigrams, bigrams, and trigrams.

Machine Learning Techniques Compared

1. Naive Bayes Classifier with Bag of Words

Approach: Probabilistic classifier based on Bayes' theorem with "naive" independence assumption between features.

Key Feature: Laplace smoothing to handle unseen words

Complexity: O(n × m) where n = number of documents, m = vocabulary size

2. K-Nearest Neighbors with TF-IDF

Approach: Instance-based learning that classifies based on the majority class of k nearest training examples.

Distance Metric: Cosine similarity for comparing document vectors

Parameter: k=5 (odd number to avoid ties)

3. Logistic Regression with TF-IDF

Approach: Linear model with sigmoid activation for binary classification.

Training: Gradient descent optimization

Parameters: Learning rate = 0.1, Epochs = 50

Evaluation Strategy

The dataset was split into training (80%) and testing (20%) sets. Each classifier was evaluated using multiple metrics:

  • Accuracy: Overall correctness of predictions
  • Precision: Proportion of positive predictions that were correct
  • Recall: Proportion of actual positives correctly identified
  • F1-Score: Harmonic mean of precision and recall

Detailed Analysis

Naive Bayes Performance

Strengths:

  • Excellent performance on this task due to strong class-specific vocabulary
  • Fast training and prediction
  • Works well with small datasets
  • Laplace smoothing handles unseen words gracefully

Why it works well: Sports and politics have distinct vocabularies with minimal overlap, which aligns perfectly with Naive Bayes' assumption that features are independent given the class.

K-Nearest Neighbors Performance

Strengths:

  • No explicit training phase required
  • TF-IDF features help emphasize discriminative terms
  • Cosine similarity is effective for text comparison

Weaknesses:

  • Slower prediction time (must compare to all training examples)
  • Sensitive to k parameter choice
  • Performance degrades with larger datasets

Logistic Regression Performance

Strengths:

  • Learns feature weights that indicate importance
  • Fast prediction after training
  • Interpretable coefficients

Weaknesses:

  • Requires careful hyperparameter tuning (learning rate, epochs)
  • Linear decision boundary may not capture complex patterns
  • Training can be slower than Naive Bayes

⚠️ Problem 4: Limitations

1. Limited Dataset Size

With only 50 articles total, the classifiers may not generalize well to real-world news data. Performance estimates have high variance due to small test set size.

2. Simplified Data

Manually created articles are cleaner and more stereotypical than real news. Real articles may contain mixed topics (e.g., politics of sports) that would confuse these classifiers.

3. Binary Classification Only

The system only distinguishes between two categories. Real news classification typically involves many categories (business, entertainment, technology, etc.).

4. No Semantic Understanding

All methods use bag-of-words or TF-IDF, which ignore word meaning and context. They cannot handle synonyms, metaphors, or sarcasm.

5. Language-Specific

The classifier is trained only on English text and would not work for other languages without retraining.

6. No Handling of Ambiguity

Articles that genuinely belong to both categories or neither category cannot be properly classified in a binary framework.

7. Feature Engineering Limitations

The current implementation uses simple tokenization without:

  • Stemming or lemmatization
  • Named entity recognition
  • Part-of-speech tagging
  • Advanced preprocessing techniques

8. Fixed Train-Test Split

Using a single random split instead of cross-validation provides less reliable performance estimates.
